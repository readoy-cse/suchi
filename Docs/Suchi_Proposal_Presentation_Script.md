# Suchi Project Proposal Presentation Script

**Language:** Simple English  
**Purpose:** Project proposal presentation  
**Presenters:** Salman, Munaim, Nahian, Sakib, and Taki

## Step 1 — Introduction (Salman)

Good morning everyone. We are here to present our project proposal, **Suchi: Academic Information and Class Communication Platform**.

The idea behind Suchi is simple: bring class routines, exam information, notices, and student contributions together in one place. Our tagline is **“Light up every update.”**

First, I will explain the problem we want to address.

## Step 2 — The Problem We Faced (Salman)

Class information is often shared through chat groups, images, and separate files. Later, it can be difficult to find the correct routine, exam details, or notice.

Older messages may look like the latest information. Also, when students share an idea or suggestion, they may not know whether it has been reviewed.

This can cause confusion and repeated questions. We believe students need one reliable place to check current class information and see the status of their contributions.

Now, Munaim will explain the solution we are proposing.

## Step 3 — The Solution We Offered (Munaim)

Suchi proposes one shared workspace for class information. Students can check routines, exam schedules, notices, and approved contributions.

Admins and Class Representatives, or CRs, can manage academic information. Students can submit an event, news item, or suggestion. These submissions go to Admins or CRs for review before they appear in the shared feed. The reviewer can approve or reject a submission and add a note.

Users can also comment on published content. Telegram notifications may be used as an optional way to share updates.

Suchi has three roles: Student, CR, and Admin. Each role has different permissions, checked by the system.

I will now hand over to Nahian to introduce the proposed technology stack and our team.

## Step 4 — A Modern JavaScript Stack (Nahian)

For Suchi, we propose a modern JavaScript stack.

The frontend uses React, Vite, React Router, and Tailwind CSS to build the web interface. The backend uses Node.js and Express to provide the application’s API. MongoDB stores the project information, and Mongoose helps structure the data.

We also plan to use Zod to validate information submitted to the system. Access will depend on user roles. Telegram is an optional integration for notifications.

These technologies give us a practical foundation for building the proposed class information platform.
